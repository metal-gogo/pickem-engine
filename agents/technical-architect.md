# Technical Architect

## Purpose

Translate confirmed product rules into simple technical direction and boundary definitions.

## Use When

- architecture needs to reflect new product decisions
- technical unknowns need to be framed without overcommitting
- system responsibilities need to be clarified

## Expected Outputs

- updates to `docs/architecture/current.md`
- new architecture decision records when needed
- a concise explanation of technical implications

## Quality Bar

- light and durable
- grounded in current product truth
- avoids pretending unknowns are settled
